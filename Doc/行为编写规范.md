# 行为（Behavior）编写规范

> 适用范围：`Script/Data/Effect/Behavior.cs` 的所有子类（`EnemyBehavior` / `BulletBehavior` / `BuffBehavior` / `RoomBehavior` / `GlobalBehavior` …）

## 一、核心原则：一个方法 = 一个行为

`Behavior` 是数据驱动的入口：资源（`.tres`）里只存一个字符串 `behaviorName`，运行时 `Behavior.Run<T>()` 用反射按名字找方法执行。

因此：

- **一个 `public` 方法就是一个行为**，方法名必须和资源里填的 `behaviorName` 完全一致（区分大小写）。
- **逻辑在一个方法里写完**。不要再往下拆 `xxxIdle()` / `xxxMove()` / `RandomDirection()` 这类私有辅助方法——那会变成"一个行为散在若干方法里"，和"一行为一方法"的模型冲突，也让别人对不上数据里的 `behaviorName`。
- 跨帧要用的数据（状态、方向、计数）放 `entity.args`，用「状态分支 + `AddTempTimer` 回调」在同一个方法里闭环。
- 参数从两处取，不要硬编码：`Arg<T>(key, 默认值)` 读**行为资源自己**的 `args`，`entity.args.Get<T>(key, 默认值)` 读**实体数据**里的 `args`。

正例（状态机也只有一个方法）：

```csharp
public void UpdateElectSpider(Enemy enemy)
{
    enemy.args.Add("elect_spider_state", "idle");
    string state = enemy.args.Get<string>("elect_spider_state");

    if (state == "move")
    {
        enemy.animNode?.Play("move");
        // 静止阶段每帧 MoveStop，所以刚切到移动时速度是 0：这时候抽一次方向走完这个阶段
        Vector2 toward = enemy.GetToward();
        if (toward == Vector2.Zero)
        {
            toward = new(game.randomSystem.Float(-1, 1), game.randomSystem.Float(-1, 1));
            if (toward.LengthSquared() < 0.0001f) toward = Vector2.Up;
            enemy.MoveToward(toward.Normalized());
        }
        enemy.AddTempTimer("elect_spider_phase", game.randomSystem.Float(1, 2), () =>
        {
            enemy.MoveStop();
            enemy.args.Set("elect_spider_state", "idle");
        });
    }
    else
    {
        enemy.MoveStop();
        enemy.animNode?.Play("idle");
        enemy.AddTempTimer("elect_spider_phase", game.randomSystem.Float(1, 2), () =>
        {
            enemy.args.Set("elect_spider_state", "move");
        });
    }
}
```

## 二、允许写私有方法的唯一场景

需要把某个行为**挂到/摘出信号**时（最典型的是 Buff 的 `onStart` 订阅、`onEnd` 退订），才写私有处理方法或内部类——因为订阅和退订必须引用同一个委托实例，必须成对存在：

```csharp
public void Flint(Entity entity, Buff buff)
{
    entity.OnShot -= OnFlintShot;
    entity.OnShot += OnFlintShot;
}

public void RemoveFlint(Entity entity, Buff buff)
{
    entity.OnShot -= OnFlintShot;
}

void OnFlintShot(Entity entity, Bullet bullet) { ... }
```

除这类"信号增删配对"外，行为方法不要再向外抽方法。

## 三、写行为方法的几条惯例

1. **有效性判断要看时机**：`onDead` / `onDeath` 这类死亡回调里，实体自己的 `isDead` 已经是 `true`，**不能**用 `Game.IsAble(entity)` 判断实体自己，否则直接 return、效果永远不生效（用 `GodotObject.IsInstanceValid(entity)` 即可）。
2. **状态只在计时器回调里翻转**，每帧只负责"按当前状态表现"。`AddTempTimer` 遇到同名计时器会直接返回 `false`，把翻转写在每帧里会导致计时器永远重建不了。
3. **一次性/随机取值只在"进入状态"的那一帧做**，不要每帧重抽。`Entity.Move()` 的 `smoothFactor` 默认是 0、速度每帧直接赋值，每帧重抽方向会让实体原地抖动而不是移动。
4. **缺参数要安全失败**：从 `args` 取不到的弹幕/资源用 `GD.PushWarning` 提示并 return，不要 NullReference。
5. **方法签名要能被反射调到**：`public`，参数个数与类型和调用处一致（见下表）。

## 四、数据字段与调用参数

`Effect` 会先把同一组参数交给 `condition`，条件通过后再交给 `behavior`。`BindBehavior` 可以按 `behaviorArray` 顺序串多个行为。

| 资源字段 | 触发时机 | 传入参数 |
| --- | --- | --- |
| `EnemyData.onGenerate` | 生成时 | `(Enemy)` |
| `EnemyData.onUpdate` | 每帧 | `(Enemy)` |
| `EnemyData.onAttack` | 攻击时 | `(Enemy)` |
| `EnemyData.onDeath` | 死亡时 | `(Enemy)` |
| `BulletData.onCreate` | 创建时 | `(Bullet, owner, null)` |
| `BulletData.onUpdate` | 每帧 | `(Bullet, float delta)` |
| `BulletData.onPhysicalUpdata` | 物理帧 | `(Bullet, float delta)` |
| `BulletData.onHit` | 命中实体 | `(Bullet, owner, target)` |
| `BulletData.onLifetimeEnd` | 寿命结束 | `(Bullet, owner, null)` |
| `BulletData.onDead` | 消亡（命中/撞墙/寿命/被杀） | `(Bullet)` |
| `BuffData.onStartEffect` | 挂载 | `(Entity owner, Buff)` |
| `BuffData.onEndEffect` | 移除 | `(Entity owner, Buff)` |
| `BuffData.onTimerEffect` | 定时触发 | `(Entity owner, Buff)` |
| `BuffData.onUpdateEffect` | 每帧 | `(Entity owner, Buff)` |
| `BuffData.onEntityHurtEffect` | 宿主受伤 | `(Entity owner, Buff, Damage)` |
| `BuffData.onEntityDeathEffect` | 宿主死亡 | `(Entity owner, Buff)` |
| `BuffData.onStackIncreaseEffect` / `onStackDecreaseEffect` | 层数变化 | `(Entity owner, Buff)` |

> 条件（`Condition`）用的是同一套参数；`GlobalBehavior` 里的条件方法通常不带参数（如 `IsPlayerAble()`），靠全局状态判断。
